**전처리 동화 이야기**

- **새로운 모험의 시작**: `src/pipelines/example_split_raw.py:1`에 있는 꼬마 요정이 등장했어요. 이 요정은 `split_by_contract_month()`(110) 마법으로 원본 CSV 하나를 계약년월별 파일로 쪼개고, 사용자가 원하면 CSV와 Parquet을 모두 만들어 줘요.
  - `.venv/bin/python src/pipelines/example_split_raw.py --raw data/raw/apt_trade/아파트(매매)_실거래가.csv --format both`처럼 부르면, 월별 스냅샷들이 `data/processed/`에 차곡차곡 쌓여요.

- **본편 전처리 마법사**: `src/etl_realestate.py:1`을 펼치면 모든 주인공들이 나와요. 이제 `--split-only` 옵션이 생겨서, 한꺼번에 돌리다 멈추는 일을 막기 위해 원본을 먼저 나눠 둘 수도 있답니다.
  - `main()`(641)에 들어오면 `list_source_files()` 요정이 `data/raw/` 아래를 순회하며 CSV 친구들을 찾고, `--split-only`를 외치면 방금 만든 `split_by_contract_month` 마법사를 불러 월별 스냅샷만 빠르게 생성해요.
  - 스냅샷만 끝내면 다음 단계에서 다시 `main()`을 부를 때 분할된 파일 없이도 전체 ETL을 이어갈 수 있어요.

- **CSV를 읽는 문지기**: `read_source_dataframe()`은 여러 인코딩을 시도해 표 머리를 찾아내고, 잘못 읽으면 친절하게 다른 방법을 시도해요.
- **이름표 정리**: `standardize_columns()`는 `거래금액(만원)` 같은 이름을 `거래금액_만원`으로 통일해 혼란을 막아요.

- **변환과 파생 계산**: `normalize_frame()`(255)부터 이어지는 함수들은 다음을 담당해요.
  - 지역 이름을 `sido`, `sigungu`, `eupmyeondong`으로 깔끔히 나누고, 숫자처럼 생긴 글자를 진짜 숫자로 만들어요.
  - `build_contract_date()`로 `계약년월`/`계약일`을 합쳐 날짜를 만들고, 거기서 `YYYYMM`, `연도`, `월`, `분기`를 도출해요.
  - `전용면적_㎡`를 토대로 `면적_평`, `가격_per_㎡`, `가격_per_평`을 계산하고, 보증금·월세가 있으면 `환산가_만원`, `추정매입가_만원`, `Yield_%`까지 붙여 줘요.
  - 이상치가 보이면 `winsorize()`로 살짝 다듬어 안정적인 수치를 만들어 줘요.

- **차원 키 부여**: `add_dimension_keys()`(321)은 `geo_hash`, `building_hash`, `date_key`를 달아 나중에 빠르게 조인할 수 있도록 준비해요.

- **월별 분석**: `compute_monthly_basics()`(380)이 거래 건수와 평균 가격을, `compute_momentum()`과 `compute_volatility()`가 추세와 변동성을 계산해요.

- **저장 요정**: `persist_transactions_csv()`와 `persist_parquet()`가 `transactions.csv`, `monthly_basics.parquet`, `monthly_momentum.parquet`, `monthly_volatility.parquet`를 `data/processed/`에 저장하고, `persist_duckdb()`는 필요하면 DuckDB에도 저장해 Streamlit 대시보드가 빠르게 쓰게 해요.

- **전체 실행 예시**:
  ```bash
  source .venv/bin/activate
  # 1) 원본을 월별 스냅샷으로만 분할
  python src/etl_realestate.py --data-root data/raw --output-dir data/processed --split-only --split-format both
  # 2) 전체 ETL 수행
  python src/etl_realestate.py --data-root data/raw --output-dir data/processed --output-duckdb data/processed/realestate.duckdb
  ```

**정리하면:** `split_by_contract_month`로 안전하게 원본을 나눠 둔 뒤, `normalize -> 파생지표 -> 월별 집계 -> 저장` 순서로 ETL 여행이 이어져요. Streamlit 대시보드를 위한 모든 데이터는 이 여정 속에서 차곡차곡 준비된답니다.

- **2025-10-01 스냅샷 추가 기록**: 모든 유형 원본 CSV(아파트/연립/오피스텔/단독, 매매·전월세, 상업용)를 2022년 1월~2023년 12월 계약월 기준으로 `split_by_contract_month` 마법으로 분리해 `data/processed/*_snapshot_20251001.csv`에 저장했어요. 월별 행 수는 원본과 1:1로 일치했고, `snapshot_date=20251001`, `contract_yyyymm` 컬럼이 정상적으로 채워진 것을 샘플링 확인했답니다. 원본 교체 이력과 대용량 파일 관리는 `.gitignore`/외부 스토리지 가이드와 함께 유지하기로 했어요.
